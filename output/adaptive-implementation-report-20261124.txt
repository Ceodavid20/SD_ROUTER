MATHEMATICS
MLU minimizes maximum utilization for a parallel-link group. For fresh averaged
main-egress demand D and eligible capacities c_i:
  target_i = D * c_i / sum(c_i)
Targets sum to D, stay nonnegative and within physical capacity, and equalize
eligible utilization. Failed/standby links get zero; report unmet demand when
healthy capacity cannot carry D. Above combined capacity, report physical excess
and publish no infeasible allocation. The 80% default is a configurable soft
target: 12 Gbps can still have a feasible 8+4 Gbps allocation, with congestion risk.

Cost = ceil((reference_bps / capacity_bps) * (1 + alpha * utilization^2)).
Defaults: reference=100 Gbps, alpha=4; both configurable. Decimal arithmetic
avoids incorrect ceil at binary floating-point integer boundaries. Calculated
cost is separate from actual OSPF metric, connection weight and actual TX.

Feedback uses error=u_second-u_first and a proportional gain, bounded step,
normalized weights, tolerance and hold-down. Initial weights follow capacity.
Discrete PCC buckets obey the step bound as well. Larger groups use a bounded
simplex projection. Unchanged decisions are deduplicated. Advisory weights never
become confirmed applied weights; there is no advisory integration wind-up.
A fully live closed loop still requires an authorized router-local actuator,
verified applied control state and real measured response.

TRAFFIC REDISTRIBUTION MECHANISM
Read-only inspection found OSPF templates (main and MTN cost 10), no mangle

Different OSPF metrics do not implement bandwidth-proportional balancing.

Preserve existing connection marks and routing tables during any future approved

configurable default denominator 300 allows finer adjustments. Actual bytes per
connection vary, so a connection percentage is never reported as measured traffic.
Official reference: https://manual.mikrotik.com/docs/high-availability-solutions/load-balancing/per-connection-classifier/

SECURITY AND COMPATIBILITY
V1/V2 poll and receipt ACK no-action contracts remain unchanged. New independent
POST /api/controller/v2/optimization and /optimization/result (under the same
/api/controller/v2 prefix) reuse HMAC-SHA512 and existing router keys. They have
strict JSON, verified HTTPS, timestamp/identity checks, source binding, independent
persistent rate/replay state, atomic authorization recheck, scoped response IDs,
versions and expiries. Extra fields, duplicate keys, NaN and RX counters are
rejected. Only delivered unexpired decisions can receive an application report.
An applied claim is rejected because execution was never authorized. Receipt
ACKs do not create application evidence. Native responses are size bounded.

Multi-interface TX extends the existing per-message contract: each authorized
interface has an independent cumulative counter, baseline and averaging series.
Nonce replay protection remains shared per identity. Changing the allowed list
disables monitoring, rotates generation and requires explicit re-enabling. New
routers stay disabled until authorized. Reset/stale/missing samples are not zero.

Workflow version 2 reuses optimization_results.json and existing projections;
legacy version 1 remains readable. New optimization_communication.json contains
only bounded protocol metadata. Latest 256 adaptive snapshots are retained;
legacy results and real segmented TX history are preserved. Actual plots are
built from stored measurements and break across reset series or long gaps.
